# UI 设计与视觉还原规范 V1.0

## 已确认的视觉基准
- 桌面首页：`design/reference/dashboard-desktop-v1.png`，原始 1536×1024，是 **桌面端学习首页** 的视觉目标。
- 手机 12 屏：`design/reference/mobile-12-screens-v1.png`，是启动页、服务器连接、登录、首页、练习模式选择、练习答题、答题结果、模拟考试设置、模拟考试中、考试结果、错题本、个人中心的移动端视觉目标。

手机图中用户名、题库进度、错题数、正确率、模拟分数、倒计时及答题选项均为设计示例，不是实际账号或后端数据。运行时必须使用真实状态/API，无数据时展示空状态。图中模拟考试设置展示的固定四级规则仍以 PRD 为准：180 题、100 分、90 分钟；不得根据示例改动规则。

## 首页布局的可复现要求
- 桌面整体：冷白/淡灰背景，柔和蓝色选中态，轻边框、轻阴影，宽松但有信息密度。不要重型玻璃拟态、彩虹渐变或大面积营销插画。
- 左侧导航固定约 250–256px；Logo 位于左上；导航依次：概览、日常练习、模拟考试、错题复习、考试记录、我的收藏；用户资料在底部。
- 主内容容器左侧留约 36px，右侧 30px 以上，最大宽度依窗口自适应；顶部状态栏约 60px，标题「从今天的进步开始。」及说明「四级理论题库 · 稳步完成每一次练习」。
- 第一行四个数据统计卡：已学习题目、整体正确率、待复习错题、最近模拟成绩。
- 第二行两块主动作卡：左「继续练习」带进度条与主按钮；右「模拟考试」包含180题、90分钟、100分信息及开始按钮。
- 第三行两块卡：左「题型掌握情况」单选/多选/判断横向进度条；右「错题复习」待复习/巩固中/已掌握统计和按钮。
- 底部「最近练习」表格：时间、练习模式、题目数量、正确率、操作。
- 布局上 4 列 KPI / 2 列主要卡 / 2 列次要卡 / 1 列表格，不得改成堆叠的营销型 Landing Page。
- 空数据时用真实空状态，例如「还没有练习记录」，不能展示伪造的 426/1283、82.6%、86.5 分或 2024 年日期。

## APP / 其他页面设计延展
- **手机 390×844**：按 12 屏基准逐页实现，顶部状态栏与页面导航、底部四到五项导航（首页/练习/考试/错题/我的）依页面需求呈现；首屏可滚动，触控目标不小于 44px，卡片适配窄屏，长题干自然换行。
- **登录/连接**：先连接服务器（扫码或输入 HTTPS 地址），再用户名+密码登录；没有注册入口。
- **练习页**：醒目题型和题号、长题干、A-E 选项、大按钮、提交后答案反馈、收藏；区分「选择中」和「已提交」。
- **考试页**：服务端剩余时间、题型、题号、答题板/题号抽屉、网络同步状态、上一题/下一题、标记与交卷；不显示答案。
- **考试结果**：分数与题型分项、正确/错误/未作答、查看详情。
- **错题页**：三种掌握状态、题型筛选、优先策略、10/20/全部、开始复习。
- **本机管理页**：状态、账号、题库导入、备份恢复；仅本机允许访问，并用真正后端鉴权限制。

## 视觉 1:1 验收方式
1. 使用 Playwright/浏览器工具，在 **1536×1024** 设置固定视口后获取真实页面截图。
2. 同样视口裁切/对齐参考图，先对照整体布局（导航宽度/横纵排布/间距），再对照组件（字号、按钮尺寸、卡片边框和颜色）。
3. 检查字体丢失、错行、布局滚动、文本溢出。可以用图像差异辅助，但不能仅用一个百分比判断合格，因为动态数据会不同。
4. 至少记录一次「不一致点 → 修改 → 重新截图」的证据。无可用浏览器工具时，说明未完成视觉验收，提供本地运行步骤，不能虚报 1:1 已完成。
5. 手机端设置 **独立的 P0-M 实现与视觉验收阶段**：12 个页面逐页在 **390×844**、**360×800** 截图、检查溢出并测试主要交互；按 `mobile-12-screens-v1.png` 对照视觉布局与控件。P0 桌面首页通过不代表手机页面已完成。
6. 禁止将参考图直接作为背景、图片切片替代交互组件、在 CSS 写死动态分数/题数以骗过截图对比。
