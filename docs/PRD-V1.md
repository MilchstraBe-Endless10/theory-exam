# 理论考试练习系统 V1.0 产品需求文档（PRD）

> 版本：V1.0 需求基线（开发前）  
> 编制日期：2026-10-16  
> 项目类型：少量用户使用的自托管理论刷题与模拟考试系统  
> 交付形态：Linux 本机服务端、Android APK、电脑浏览器管理界面、GitHub 仓库与 Releases  
> 说明：**【已确认】**表示用户已经明确决定；**【默认方案】**表示为推进开发采用的合理默认值，可在实施前调整；**【后续】**表示不纳入 V1.0。

---

## 1. 项目概述

### 1.1 背景

当前已有《四级理论试题.xlsx》，需要通过一个导入按钮将试题转换为可在手机上练习和模拟考试的题库。系统供少数熟人使用，各自有独立账号、刷题进度、错题本和考试成绩。用户自己的 Linux 电脑作为唯一业务与数据库服务器；手机是客户端，支持局域网连接和经现有 **frp 内网穿透**连接。GitHub 仓库作为软件介绍、源码与 APP 安装包的下载入口。

### 1.2 核心目标【已确认】

1. 一键导入 Excel 题库，识别题型、题干、选项、正确答案，并展示校验结果。
2. 提供顺序练习、随机练习、按题型练习、未做题目练习及收藏功能。
3. 提供正式模拟考试：**120 道单选 + 20 道多选 + 40 道判断，共 180 道，90 分钟，100 分满分**。
4. 自动记录错题并支持跨轮次掌握状态跟踪、按题型筛选、随机/薄弱题优先复习。
5. 账号由本机服务端统一创建，不开放手机 APP 自助注册；学习数据相互隔离。
6. 服务端集中存储用户、题库、考试及答题记录，允许手机异常退出后恢复。
7. 后续能导入三级理论题库及其他题库，考试规则支持按题库独立配置。
8. GitHub Releases 发布 Android APK 和服务端安装包，尽量简化安装与维护。

### 1.3 明确不做【已确认】

- 不做 AI 题目解析、AI 生成答案或自动补全解析。
- 不做教师管理后台、班级管理、排行榜、社交、积分商城或付费功能。
- 不做复杂多级权限、审批流程、第三方账号登录或用户自助注册。
- 不做云端题库/云数据库；公网 VPS/frps 只承担网络转发，不保存业务数据。
- V1.0 不做完整离线刷题或离线考试；只做异常断线的临时答案保护。

## 2. 使用对象与权限

| 对象 | 使用入口 | 可进行的操作 |
| --- | --- | --- |
| 本机维护者 | 本机或受限制的管理页面 | 初始化、导入题库、设置考试规则、创建/禁用账号、重置密码、备份恢复、查看服务状态 |
| 普通用户 | Android APP；可选桌面学习网页 | 登录、选题库、刷题、考试、错题复习、收藏、查看自己的历史成绩 |

**权限约束**：系统仅区分维护者与普通用户，不引入教师、班级、部门等角色。普通用户不能访问管理 API，也不能读取或修改别人的题目进度、作答记录和成绩。管理员默认只维护账号与服务端，用户详细作答信息不作为管理界面的必选功能。【默认方案】

### 2.1 账号规则

- 【已确认】账号只能由本机服务端创建；APP 不出现“注册”入口。
- 用户名唯一；创建账号时设置初始密码，登录后可自行修改密码。【默认方案】
- 密码只保存安全哈希（推荐 Argon2id），不得明文存储或写入日志。
- 支持禁用账号、重置密码；不将“直接物理删除账号及成绩”作为普通操作。【默认方案】
- 登录状态使用可撤销的会话/令牌，并且服务端校验访问权限。账号禁用后现有会话应失效。

## 3. 原始 Excel 数据与导入要求

### 3.1 原始文件核验结果（基于用户提供的文件）

- 文件：`四级理论试题.xlsx`
- 工作表：`客观题`
- 表头（8 列）：`题型 / 题干 / 选项A / 选项B / 选项C / 选项D / 选项E / 答案`
- 有效数据：**1,283** 行，其中**单选 845**、**多选 38**、**判断 400**。
- 1,283 行均有题干与答案；当前答案字符均对应非空选项。
- 文件没有“解析”列，V1.0 不虚构题目解析。
- 依据去除部分空白/不可见字符后的题干文本统计，有**64 组重复题干、65 条超出首条的重复记录**；其中**33 组跨题型**，其答案字符串也不同。它们可能是不同命题方式，不得仅按题干自动删除。
- 注意：原始文件同时存在“对/错”“正确/错误”两种判断题选项形式；以每题实际选项及原答案字母为准。

### 3.2 导入流程【必须】

1. 本机维护者在“题库管理 → 导入题库”点击按钮，上传 `.xlsx`（后续可扩展 `.csv`）。
2. 系统识别工作表与列名；首先支持上述 8 列模板。存在多工作表时允许选择待导入工作表。【默认方案】
3. 解析并预览：题量、题型分布、答案完整性、异常行、重复题提示。
4. 对每一行校验：题型合法、题干非空、至少包含所需选项、答案仅引用已存在的选项、判断题结构合理；多选正确答案按字母集合处理。
5. 管理者确认后，**事务性导入**：全部合格才批量导入；如存在错误，先提供错误行下载/查看并允许取消或只导入合法行（默认整批阻止）。【默认方案】
6. 导入完成后可以按题型筛选、搜索、查看题目和原始 Excel 行号。
7. 完全相同的文件重复上传时提示已存在，不静默重复创建整套题库。

### 3.3 数据保存规则

- 保存题干及选项原文、题型、正确答案集合、源文件名、工作表、源行号、题库版本号。
- 清理不可见字符只用于**搜索和查重对比**；展示原文时不得擅自改写专业内容。
- 题目应有内部稳定标识；用户答案、收藏、错题状态与具体题库/题目关联。
- **重复题默认保留并提示**，尤其不合并不同题型、选项或答案的记录。
- 导入修订版需创建新题库版本或明确的差异确认流程；已经完成的历史试卷与成绩必须关联当时的题目快照，不随新版改变。
- 若某题型不足组卷所需题数，禁止按该规则开始考试并清楚提示缺少多少题。当前四级题库满足 120/20/40 的数量要求。

## 4. 题库管理与扩展

- 【已确认】V1.0 首先导入四级理论题库，但架构必须支持后续导入三级理论题库。
- 每份题库含：名称、描述、题目集合、版本、启用状态、考试规则。
- 各用户对各题库的练习进度、收藏和错题记录分别统计。
- 【默认方案】题库可启用/停用；停用后不允许新练习/新考试，但历史成绩可查询。
- 【默认方案】三级题库沿用同一导入模板；如题型或表结构不同，需要在导入前校验并提示，不做未经确认的自动猜测映射。
- 【默认方案】四级考试规则设为固定预设；其他题库由维护者配置其抽题数量、每题分值和考试时长，不能将四级规则写死在程序逻辑中。

## 5. 日常练习

### 5.1 练习入口【必须】

- 顺序练习：按题库内部顺序逐题作答，可续接上次进度。
- 随机练习：随机选题，可按题量限制。
- 题型专项：单选、多选、判断题独立练习。
- 只练未做：只选本用户从未正式提交过答案的题目。
- 收藏练习：用户自主收藏题目并再次练习。【默认方案】

### 5.2 答题交互

- 单选/判断只允许选一个；多选支持多项选择及取消。
- 练习模式**提交后立即判对错**，显示正确答案；原表无解析时显示“原题库未提供解析”。
- 记录练习时间、题库、题目、用户答案、对错结果、来源练习模式；用户切换设备时从服务器恢复进度。
- 练习数据应在每次提交后持久保存；手机暂时断线应显示失败或待同步，不得错误显示服务器已保存。
- “题目已接触”定义：至少有一次正式提交作答；仅打开题目不计入。

## 6. 模拟考试

### 6.1 四级理论考试规则【已确认】

| 题型 | 抽取题量 | 每题分值 | 小计 |
| --- | ---: | ---: | ---: |
| 单选题 | 120 | 0.5 | 60 |
| 多选题 | 20 | 1 | 20 |
| 判断题 | 40 | 0.5 | 20 |
| **总计** | **180** | — | **100** |

- 考试总时间 **90 分钟**，服务器根据开始时间确定截止时间。
- 每场考试从当前题库对应题型**随机抽取不同题目记录**，同一场内不重复；不同场考试允许出现相同题目。
- 【默认方案】试卷按“单选 / 多选 / 判断”分区展示，题目在各区内随机排序；选项顺序保持原 Excel 顺序，防止答案错位。
- 单选与判断选对得分，选错或未选 0 分；多选必须与正确选项集合**完全一致**才得 1 分，漏选、多选、错选、未选均 0 分。【默认方案】
- 不扣倒分、不额外加分、不折算；最高 100 分。
- 【默认方案】及格线 60 分，在维护端可单独配置，不影响原始考试成绩。

### 6.2 开始考试

1. 选择题库，查看考试说明：题型数量、分值、时长、及格线。
2. 点击开始，服务端生成固定的考试会话、题目快照与试卷顺序、起止时间。
3. 【默认方案】一个账号同一时刻最多存在一场进行中的考试；重复点击“开始”应恢复现有考试而不是重建。

### 6.3 考试中

- 顶部显示**以服务器截止时间为准**的剩余时间、当前题号、作答数量和网络同步状态。
- 支持上一题、下一题、跳题导航、标记待检查、修改已选答案。
- 考试中绝不显示正确答案或得分。
- 作答每次变化时，手机先写入临时待同步记录，再发送服务器；服务器返回确认后才标注“已同步”。
- 支持主动交卷（未做完时二次确认）；达到截止时间由服务端自动结束并结算。
- 未作答题按 0 分处理；为避免错误统计，未作答不自动增加“答错次数”，可单独归入“待练题”。【默认方案】

### 6.4 交卷与历史成绩

- 只在完成/超时结算后向用户显示总分、各题型得分、正确题数、错误题数、未作答题数、用时和及格状态。
- 支持查看每一道题的题干、本人答案、标准答案、对错结果、是否计分。
- 考试记录永久关联本场题目快照；题库升级后仍可完整复盘旧试卷。
- 不允许普通用户修改分数、重写历史答案或直接删除历史考试记录。【默认方案】
- 交卷和评分必须是幂等操作；重试请求不得生成重复成绩。

## 7. 错题复习与掌握状态

### 7.1 错题来源【已确认】

- 顺序、随机、专项练习答错后立即更新错题；模拟考试结束评分时统一更新。
- 同一道题同一用户在错题本仅有一条状态记录，但保留作答历史、错误次数、最近答错时间。
- 题库之间、账号之间的错题互不混合。

### 7.2 掌握判定【已确认】

状态流转：

`首次答错 → 待复习（连续正确=0） → 第一轮复习答对 → 巩固中（=1） → 不同轮次再答对 → 已掌握（=2）`

- **必须在不同的错题复习轮次连续答对两次**，才算已掌握。
- 同一题在同一轮复习最多贡献一次有效连续正确次数。
- 复习期间若再次答错，连续正确数清零、错误次数增加、状态回到“待复习”。
- 普通练习和考试再次答错，会将已掌握题重新激活为待复习；普通练习或考试答对，不直接增加复习掌握进度。【默认方案】
- 已掌握只是从默认待复习列表隐藏，不物理删除，仍能筛选查看和手动复练。

### 7.3 错题出题方式【已确认，可组合】

1. **题型筛选**：全部题型混合 / 仅单选 / 仅多选 / 仅判断。
2. **抽题策略**：随机；或“掌握度最低优先、再按历史错误次数从高到低，同优先级随机”。
3. **本轮题量**：10 道 / 20 道 / 全部可用错题。【默认方案】
4. 上述选择能自由组合。例如“仅多选 + 薄弱题优先 + 10 道”。
5. 匹配题量不足时，使用实际可用题量并明确提示；复习退出时已完成题目的结果保留，未回答的不改变掌握状态。

### 7.4 收藏和待练

- 收藏独立于错题，可收藏已答对但不熟悉的题目。
- “未做题”与“曾经做错”是不同状态：未提交答案的题目不能简单视为答错。
- 统计显示已接触题目数、未接触题目数、待复习数、巩固中数和已掌握数。

## 8. 手机 APP 与本机服务端连接

### 8.1 部署边界【已确认】

- 业务 API、账号库、题库、考试状态及 SQLite 均部署在用户的本机 Linux 电脑。
- **现有 frp** 负责外网访问：公网已有 `frps` 服务端，本机运行/复用 `frpc`，将外网 HTTPS 入口转发到本机应用入口。若现有 frp 的实际拓扑不同，以既有服务为准，不强行重建。
- 电脑/手机处于同一局域网时，允许直接访问本地服务；外网使用经过现有 frp。
- 不允许将数据库文件、账号明文、题库数据或管理接口直接暴露到公网节点。

### 8.2 网络拓扑

```text
手机 Android APP
   ├─ 局域网：HTTPS → 本机应用入口 ┐
   └─ 外网：HTTPS → 既有公网域名/IP:端口
                    → frps → frpc ─┤
                                     ▼
                           本机 HTTPS/反向代理
                                     ▼
                         Fastify API + SQLite

本机浏览器 → 仅本机可访问的维护管理界面
```

说明：实际使用 IP:端口时也必须保证 APP 到公网入口具有可信 TLS。**frp 隧道传输加密不等同于 APP 公网入口自动具备 HTTPS**。具体映射类型需按现有 frp 配置决定。

### 8.3 首次绑定与自动连接【默认方案】

1. 维护者设置“局域网 HTTPS 入口”和“frp 外网 HTTPS 入口”。
2. 服务端显示连接二维码，二维码只含连接地址、服务器标识及必要的公开校验信息，**不得携带用户密码、管理令牌、frp 密钥**。
3. APP 扫码或手动输入地址，验证受信任证书及服务器身份后绑定，进入账号登录。
4. APP 后续自动尝试已绑定服务器；优先同一域名的内外网分流（若已有 DNS 条件允许），否则采用两个地址自动探测/回退。
5. 切换连接路径不改变用户身份、服务器数据、考试编号或试卷。
6. 无可用服务端时明显提示“无法连接”，允许重试/修改地址，而非无限加载。

### 8.4 安全要求

- 公网入口必须使用受信任的 HTTPS，禁止正式版绕过证书验证或默认使用公网明文 HTTP。
- 本机管理界面只监听本机地址或受控管理网络；**不得通过 frp 对外发布维护接口**。
- 服务端要做账号鉴权、登录限速、输入校验、题库文件校验和日志敏感信息脱敏。
- frp 认证密钥与 TLS 私钥放在系统受限配置文件或环境变量中，不进入 GitHub 仓库或 APP。
- 若穿透服务异常，局域网直连应继续可用；若本机服务端停机，则两种网络方式都无法进行在线业务。

## 9. 考试中断、恢复与同步

### 9.1 核心原则【必须】

- **以服务端时间计时与结算**，不能依赖手机持续后台倒计时；锁屏、后台、短暂断线不暂停考试。
- 一场考试生成后，题目、顺序、答案规则与截止时间固定；恢复时不重新抽题。
- 服务端数据库保存每题最新有效答案；每次答案写入携带版本号/序号，避免网络重试中的旧答案覆盖新答案。
- 正式状态分为：未开始、进行中、已交卷、超时结算、异常作废。【默认方案】

### 9.2 中断场景

| 场景 | 期望行为 |
| --- | --- |
| 锁屏/切换 APP | 正常计时，返回时刷新服务器剩余时间及同步状态 |
| APP 强制关闭/手机重启 | 再次登录后继续同一场未完成考试 |
| Wi-Fi 与移动网络切换 | 自动重连、对齐服务端答案版本，不创建新考试 |
| 短暂断网 | 手机本地暂存未同步选择，明确显示“待同步” |
| 截止前重新联网 | 重新提交待同步的合法答案，并以服务器确认为准 |
| 超过截止仍未同步 | 默认只计入截止前服务器已确认的答案，**不接受超时补交** |
| 服务端重启 | 数据库恢复进行中考试；若已过截止，按已保存答案结算 |
| 手动交卷重复点击 | 服务端幂等处理，只产生一个最终结果 |
| 同账号两台设备同时编辑 | 【默认方案】只允许一个活跃作答设备，第二台需显式接管并使第一台编辑失效 |
| 服务端长时间故障 | 【默认方案】维护者可将异常场次标记作废并允许重新考试，保留原始记录 |

> 重要限制：V1.0 不承诺长时间离线也能完成计分。离线临时草稿是防数据丢失机制，不是服务端认可的最终交卷证据。APP 必须清楚区分“本地暂存”和“服务器已同步”。

## 11. 服务器程序与数据设计

### 11.1 技术栈【默认方案】

- 前端：React + TypeScript + Vite。
- Android：Capacitor 封装同一套学习界面，生成已签名 APK。
- API：Node.js + Fastify。
- 存储：SQLite，推荐 WAL、外键约束、事务机制和应用层数据迁移。
- Linux 服务：原生 `systemd` 启动/重启；不强制 Docker。Podman 可作为后续可选安装方案。
- 连接：现有 frp（`frps`/`frpc`），公网 HTTPS 入口按既有环境适配。

### 11.2 核心数据实体（逻辑模型）

`users`（用户）、`sessions`（登录会话）、`question_banks`（题库）、`bank_versions`（题库版本）、`questions`（题目）、`import_batches`（导入批次）、`practice_answers`（练习作答）、`question_progress`（已做/未做）、`wrong_question_states`（错题掌握状态）、`review_rounds`（错题复习轮次）、`favorites`（收藏）、`exam_sessions`（考试场次）、`exam_papers`（本场题目与快照）、`exam_answers`（考试作答）、`backup_records`（备份记录）。

**必须满足的数据约束**：

- 用户与题库 ID 不能被客户端任意伪造或越权访问。
- 每个账号针对同一题目有唯一错题状态，多个历史作答单独保留。
- 每场考试的题目快照和分数不可被题库修订覆盖。
- 相同请求重发（导入确认、保存答案、交卷）要保证幂等或冲突可识别。
- 数据库迁移需支持向前升级并提供升级前备份。

### 11.3 API 能力（开发接口清单）

- 登录/退出/修改密码/当前用户信息。
- 获取服务端身份、可用入口、健康状态。
- 获取题库列表、题库信息、题库题型统计。
- 开始练习、提交答案、查询进度、收藏、获取错题复习题目与提交结果。
- 创建/恢复考试、读取固定试卷、保存单题答案、查看同步版本、交卷、查询成绩与考试明细。
- **本机受限管理接口**：创建/禁用账号、导入预览/确认、题库版本管理、考试规则配置、备份/恢复。

实际路由路径、请求结构、数据库字段与错误码在技术设计阶段细化；不得因接口名称变动影响以上业务语义。

## 12. 备份、日志与运维

- 本机集中保存 SQLite 数据库与必要题库元数据；不把数据库放到 frps 公网节点。
- 【默认方案】每天自动生成一次一致性备份，保留近 7 次日备份；提供手动备份、下载/导出和恢复。
- 恢复操作须二次确认，并在恢复前生成当前数据的安全备份；不得直接复制正在写入的 SQLite 主文件作为在线备份手段。
- systemd 配置开机自启、崩溃自动重启与合理日志轮转；部署说明应提示电脑睡眠/关机时服务不可用。
- 日志用于定位连接、导入、考试和数据库错误；不得记录用户明文密码、完整会话令牌或 frp 密钥。

## 15. 关键验收标准（V1.0）

1. **原始文件**：导入指定《四级理论试题.xlsx》后识别 1,283 条题目，分别统计 845/38/400；答案合法且重复题提示不造成误删。
2. **多账号**：至少 3 个账号独立使用；互相无法读取修改练习数据、考试成绩和错题状态。
3. **正式考试**：每场恰好抽取 120 单选、20 多选、40 判断，共 180 条不重复题目记录；时长 90 分钟、满分 100 分，判分规则正确。
4. **题目复盘**：交卷后可逐题查看本人答案和标准答案；旧考试不因新题库版本而变化。
5. **错题规则**：同一道题在两次**不同复习轮次**连续正确才成为已掌握；中间再次答错则重置；混合/按题型/薄弱题优先均能组合。
6. **续刷与统计**：正常退出后登录可恢复练习进度；未做题数和题型正确率与实际记录一致。
7. **断线恢复**：锁屏、关闭 APP、切换局域网/外网后仍能继续原考试，已由服务端确认的答案不丢失。
8. **超时结算**：无论手机是否在线，服务器均按固定截止时间结束考试；不得因为客户端时间变化延长考试。
9. **进程恢复**：本机服务端重启后，未结束考试和题目快照仍存在；重复交卷不会重复结算。
10. **安全性**：APP 公网 HTTPS 可用；普通用户无法调用管理接口，凭证不出现在仓库与日志中。
11. **发布升级**：可从 GitHub Releases 下载并安装 APK；服务端升级后原有数据库及用户历史记录保持完好。
12. **数据保护**：能完成备份、恢复并验证恢复后的账号、题库与成绩一致性。

## 附录 A：frp 接入原则与官方资料

- 正式运行优先使用可信的 HTTPS 入口；已有 `frps` 和 `frpc` 仅用于网络转发，不重建既有系统。
- 新版 frp 配置优先使用 TOML；官网说明自 v0.52.0 起支持 TOML/YAML/JSON，旧 INI 格式已弃用。
- 具体代理可使用 TCP / HTTP / HTTPS 等类型，必须依据现有域名、TLS 终止位置与 `frps` 端口设置选择，不能未经核对直接复制示例配置上线。
- 官方文档：https://gofrp.org/en/docs/features/common/configure/  
- 代理参考：https://gofrp.org/en/docs/reference/proxy/  
- HTTP/HTTPS 说明：https://gofrp.org/en/docs/features/http-https/  
- 官方仓库：https://github.com/fatedier/frp

## 附录 B：关键业务名词

- **题库**：一类考试/职业等级的题目集合。
- **题库版本**：一次正式发布或修订后的题目快照。
- **练习轮次**：一次开始到主动结束/完成的错题复习会话；同题在同轮只贡献一次掌握进度。
- **考试场次**：某个用户一次固定的模拟考试，保存不可变的本场题目与截止时间。
- **已同步**：服务器已经确认持久保存的作答状态。
- **待同步**：手机端已临时记录但服务器尚未确认的作答状态。
- **已掌握**：同题在不同错题复习轮次连续答对至少两次后的学习状态，不意味着永久移除题目。
